# Tasks: Nightly Health Digest

Delivery strategy: ask-on-risk. Single writer. All verifications are offline — mocked `ghagga-db`, injected forge verbs, injected queue seams, fake timers for cron logic, no live Redis in CI — except the explicitly optional Docker-gated PG integration in T3.1. The eight design decisions are BINDING: append-only `digests` table with partial-unique one-open index (D1); `fileRisk = Σ |SEVERITY_WEIGHTS[severity]| × recency` (≤7d ×1.0 else ×0.5, 30-day window, top 10, tiebreak blast-radius dependents then path asc, D2); shared `0 3 * * *` UTC + worker concurrency 2 (D3); BullMQ default missed-run semantics, no catch-up loop (D4); status enum `POSTED | SKIPPED | FAILED` (D5); title `GHAGGA Health Digest`, marker `<!-- ghagga-digest -->`, DB `issueNumber`-only lookup, rotate on closed/404 (D6); reconciler at startup + both settings routes via `upsertJobScheduler`/`removeJobScheduler` (D7); `digest.ts` queue mirrors `review.ts`, worker in-process, no env gate (D8). **Apply order: S1 → S2 → T4.1 → S3 → T4.2** — the S4 formatter is pure and lands BEFORE the S3 worker so worker tests exercise the real body bytes.
